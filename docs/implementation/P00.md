## Security findings and retests

| Finding / red hypothesis | Fix / blue response | Result |
| --- | --- | --- |
| Tests can inherit live DATABASE_URL or dotenv contents | Early environment reset, fixed fixture selector, dotenv disabled; no external route in test namespace | Canary denials and legitimate fixtures pass |
| libpq bypasses a Python socket-only guard | Guard `psycopg.connect` and `Connection.connect`; refuse alternate DSN/host overrides; Docker remains the actual boundary | Both alternate connection paths denied |

| Flat route enumeration omits included authentication routes | Inventory effective route contexts and retain explicit expected endpoints | Contract regression passes |

The dependency fixes are prepared in code; the existing live image is not
patched until the normal reviewed deployment/rebuild. No exploitation attempt
against the live service was made. Dependency advisories are time-sensitive
and must be rerun on each PR. A clean scan is not proof of absence of flaws.

## Current API/config contracts

| Route | Current contract |
| --- | --- |
| GET `/api/health` | Public liveness; `status`, `database_configured`, `model`, `retrieval`; no DB/model work |
| GET `/api/models` | Public model list, entries `id`, `name`, `description` |
| GET `/api/auth/config` | Configured Google client ID, nonce/CSRF challenge and signed challenge cookie; 503 if auth unconfigured |
| POST `/api/auth/google` | JSON `credential` (1–8192 chars); verifies Google identity, signed challenge, Origin and CSRF; creates signed session |
| GET `/api/auth/me` | Session required; `user`, `csrf_token`, `can_query` |
| POST `/api/auth/logout` | Session, Origin and CSRF required; 204 clears browser cookies; copied cookies currently expire separately |
| POST `/api/query` | Session, CSRF and explicit allowlist required; trimmed `question` 1–2000 chars, optional `model` = ollama/gemini |
| GET/HEAD `/openapi.json`, `/docs`, `/docs/oauth2-redirect`, `/redoc` | Default backend documentation routes; not a statement about public proxy reachability |

Query responses retain `status`, `sql`, `model`, `message`, `tables`,
`visualizations`, `kpis`, `error`; outage responses use 503 with safe user-facing
messages. Gemini-not-configured is 400; rejected SQL is currently a 200 error
envelope; validation errors are 422. All `/api/` responses carry no-store and
Vary: Cookie. Existing regression suites cover auth, cookie, authorization,
transport and response details; this phase does not redefine those contracts.

Configuration remains in the existing typed Settings object and `.env.example`.
Secrets are DATABASE_URL, INDEXER_DATABASE_URL, GEMINI_API_KEY and SESSION_SECRET;
no values were copied into evidence. Google client ID and APP_ORIGIN are public
configuration. Authorization still uses explicit Google-sub/email allowlists;
sign-in alone does not grant data access. P02–P04 introduce the separate private
application DB and durable identities/sessions without changing the analytical
database's ownership or treating its credentials as account access.
