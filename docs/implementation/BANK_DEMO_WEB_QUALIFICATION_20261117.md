## Limits and preserved failures

Backend first failed because the closed route inventory omitted the two new
routes; only those exact entries were added before a full rerun. Browser setup
failures exposed Windows environment matching, native keyboard-event and
synthetic-history fixture mistakes. A mobile test assumed16px instead of the
actual14px baseline; measured doubling and all geometry/target assertions now
pass without a product CSS change. Initial proxy/build setup failures are also
retained. No failed receipt was overwritten or relabeled as passing.

The browser journeys use mocked HTTP projections, separately cross-checked with
the actual API and canonical original report data. They are not a single
browser-to-real-backend acceptance run, physical device/assistive-technology
acceptance or production-edge test. The native SQL archive is synthetic and
app-only; encrypted independent retention, original-key production recovery,
whole-host authority recovery and the full cutover operator remain unproved.

This is local qualification, not deployment or bank certification. The current
picomatch dependency audit holds release. Real-bank connectors/IdP, bank policy,
durable bank approvals/execution and broad bank training are future work. The
future goal is a small data/identity adapter plus configuration for compatible
approved systems; these fictional DTOs and personas cannot authorize real data.
