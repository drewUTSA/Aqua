## Changes and rationale

- Catalog loading uses three queries and reviewed bank/Pagila manifests. Static
  dictionaries replace row samples and live comments in provider metadata.
- SQL validation resolves physical tables using lexical CTE scopes, preserves
  PostgreSQL identifier semantics and qualifies public tables. Unreviewed or
  unsafe functions fail closed. Execution excludes public-schema function
  overloads without breaking ordinary unqualified table lookups.
- Fixed diagnostics replace database/provider exception text in responses,
  repair prompts and boundary logs. Permission/unknown failures do not retry.
- Retrieval authorization/integrity failures stop. Only classified outages may
  fall back within the same authorized dataset; retrieved schema text is rebuilt.
- Cache keys preserve literals and include server-owned identity and policy
  revisions. TTL, entry and encoded-byte caps bound reuse/storage.
- Nginx ignores forged client identity headers for quotas, limits equivalent
  query/login routes together and keeps logout/health available during abuse.
  A reproducible two-worker proxy exercise now runs in the existing CI workflow.

See [the boundary specification](../security/P01_BOUNDARIES.md) for the provider
contract, complexity analysis, exact limits and durable throttling design.
`backend/nl2sql/db.py`, `backend/nl2sql/config.py` and all `db/` files retain their
base hashes. No account database or hosted business-database migration is included.

## Red, blue and paired retest

| Attack hypothesis | Original result | Implemented defense and retest |
| --- | --- | --- |
| Case/spacing/punctuation or separator changes collide in cache | Four failing regressions | Exact structured keys; principal/dataset/grant/schema/context/policy partitions; expiry and byte-cap tests |
| Raw errors or live metadata disclose a synthetic canary | Canary appeared in baseline error/schema tests | Fixed SQLSTATE messages, safe provider errors, zero row sampling, reviewed metadata; prompt/client/log assertions pass |
| Permission-denied retrieval widens context | Baseline fell back; arbitrary retrieved schema was trusted | Denial stops before generation; known outage fallback stays authorized; safe action log asserted |
| Qualified schemas, quoted names or unrelated CTEs escape the relation policy | Six failing baseline cases | Lexical scope, exact relation identity and public qualification; adversarial variants and legitimate CTE/aggregate results pass |
| A public function overload impersonates an approved built-in | Disposable fixture demonstrates ordinary lookup reaches its canary | Catalog-only function resolution rejects the overload; legitimate lower-case conversion still succeeds |
| Forged IP/cookie headers refresh query budgets | Original proxy admitted 12/12 requests | Same peer budget admitted 6 and rejected 6; rejected work never reached the fake upstream |
| Route aliases/concurrency/cooldown undermine enforcement | Exercised against corrected config | Query/login slash variants, separate buckets, four-caller wave, oversized body rejection and successful cooldown recovery pass |

Baseline red suite had 13 failing tests on bank and 14 on Pagila; the metadata
canary case is Pagila-specific. The final suite expands those regressions.
Expected baseline failures are retained as evidence, not counted as passing tests.
The blue proxy run records 14 total fake-upstream calls across ordinary queries,
auth, logout, health and recovery; each rejected request is checked against the
counter. Its latest 31 HTTP requests completed in 18.1 seconds. Resource snapshots are
post-run observations, not peak measurements or a production load benchmark.
