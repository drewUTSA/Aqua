## Implemented scope

- Responsive charcoal/Opal chat-only home, static decorative specks and exact
  local Figma assets. The semantic composer needs no WebGL; Enter, Shift+Enter,
  IME, send/stop, model choice, suggestions and visit-local recents remain.
- Explicit local routes, unknown-route recovery, public policy pages, an account
  menu and a read-only Settings shell. Settings/back preserves the mounted
  conversation, scroll and draft. Unsupported preferences, project search and
  persistence are not presented as working controls.
- The operator selects `VITE_AQUA_UI_SHELL=opal|legacy` at build time, exposed as
  Docker/Compose `AQUA_UI_SHELL`, default Opal. Legacy restores classic blue/glass
  presentation while sharing the current composer, account owner, native dialog,
  dual-login/routes and security controls. Invalid values fail the build.
- Legal navigation preserves an existing hidden account owner through pending or
  failed logout; direct public policy visits need no auth bootstrap. Settings
  policy links use SPA navigation. Policy descriptions now reflect private
  account/session storage and enabled password/email/model processing accurately;
  final operator/legal review remains a release task.
- Visit-local title search checks at most 100 conversations, 512 characters per
  title and 120 query characters, without network calls or message-body search.
- Google's supported GIS control plus independent password login. Registration
  requests only an email; a fresh password is established after mailbox proof.
  Verification and reset complete without automatic login or dataset grants.
- Fresh action-specific bootstrap before exactly one password POST, fixed safe
  errors, bounded response/deadline, deliberate retry, Retry-After cooldown and
  duplicate-submit prevention. No automatic POST retry, arbitrary redirect or
  email resend loop. Managers, autofill, paste and Unicode passphrases work.
- Email fragments are captured before UI/SDK setup and cleared immediately.
  Proofs/passwords remain in page memory; errors do not reflect server bodies.
- Canonical account ownership fences private state. Pending/failed logout keeps
  drafts mounted but hidden/inert. Confirmed logout/account switch clears them.
  Account access is independent of analytical entitlement: an authenticated
  account without a dataset can reach Settings and sign out, but cannot query.
- Metadata-only cross-tab invalidation on confirmed login/logout. Reset locks
  private state at both request start and completion, including an ambiguous
  response and a second tab that revalidated while the reset was pending.
  Foreground session revalidation is bounded to one attempt per ten seconds.
  No identity, token or CSRF value is broadcast or persisted in browser storage.
- Failed query drafts recover without overwriting text typed while waiting.
  Browser conversations are capped at 100; server admission remains independent.
- Frontend Docker builds exclude `.env` files and force production demo flags
  off. A synthetic environment canary verified exclusion from the build and
  runtime assets. Existing locked dependencies are retained.

## Bounded work and ownership

Password response parsing is O(response bytes), with a 16 KiB response ceiling
and a 30-second deadline. Each explicit submission performs one bootstrap and
at most one POST; a page-level guard prevents overlapping submissions. These
bounds control work and memory rather than relying on an unqualified Big-O claim.

Visit-local conversation lookup/update may scan the conversation collection,
O(C), with C capped at 100. This does not establish durable-history performance;
P06 owns database pagination/index plans and P12 owns measured capacity. The
canonical account key and response-generation checks prevent state reuse across
accounts; they are ownership controls, not algorithmic optimization. Foreground
session revalidation is bounded to one attempt per ten seconds per tab. Backend
query, session, hashing and admission algorithms are unchanged from P04. Bounded
title search has a conservative O(C × T × Q) substring-comparison worst case,
where C <= 100, T <= 512 and Q <= 120; no server query occurs per keystroke.

## Repeatable browser gates

The workflow adds synthetic browser and real private-database browser gates for
both shell variants. It fails if Chrome is unavailable. These are CI steps; their remote
result remains pending the human push. On Linux, from the repository root with
Python 3.12, Node, Docker and Google Chrome installed, the focused reproduction is:

```bash
docker build -t aqua-runtime:check -f backend/Dockerfile .
docker pull postgres@sha256:3645570cccdfa447589da9f57dd740faa29b30938e861289a5574b6ca6b03826
npm --prefix frontend ci --ignore-scripts --no-fund
export VITE_AQUA_UI_SHELL=opal
export AQUA_P05_EXPECTED_SHELL=opal
VITE_AQUA_DEMO_MODE=false VITE_AQUA_USE_MOCK=false npm --prefix frontend run build
export AQUA_CHROME_EXECUTABLE="$(command -v google-chrome)"
test -x "$AQUA_CHROME_EXECUTABLE"
node frontend/checks/p05-browser.mjs
export AQUA_P05_BRIDGE_EXECUTABLE="$(command -v python)"
export AQUA_P05_BRIDGE_ARGS_JSON='["tools/checks/p05_browser_backend.py","--image","aqua-runtime:check"]'
node frontend/checks/p05-real-backend-browser.mjs
```

The Python executable must resolve to an absolute path. No SSH account, server
key or production environment file is required. The fixture creates bounded,
network-isolated synthetic resources and requires confirmed cleanup for success.
`AQUA_P05_DIST` may select an absolute directory of extracted release assets;
`AQUA_P05_ARTIFACT_DIR` selects an absolute report directory. Both browser reports
record the loaded HTML/JS/CSS hashes. The recorded release runs used the exact
candidate image assets rather than a separately rebuilt development bundle.
Repeat with both shell variables set to `legacy` and a separate artifact directory.
Final follow-up runs must use the respective built image's assets; neither an old
bundle nor an Opal-only pass proves that the legacy build preserves secure auth.
